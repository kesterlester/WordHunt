\section{Motivation}

\texttt{wordhunt.py} / \texttt{wordhunt2.py} (in the parent directory) are
recreational assistance tools for a daily puzzle: 25 letters (one letter of
the alphabet entirely absent) fill a $5\times5$ grid; a single 5-letter
dictionary word is spelled along one of 12 lines (5 rows, 5 columns, 2
diagonals); the player learns, one query at a time, where a chosen letter
actually sits in the grid (the grid is a full bijection over every
non-excluded letter, so this is disclosed regardless of whether that
letter turns out to be part of the answer word).

Every statistic those tools compute --- raw letter frequency, Zipf-weighted
frequency, positional entropy, a proposed Bayesian ``leading candidate''
posterior --- turned out, on inspection, to be a \emph{one-step heuristic}
resting on an unstated and unverified assumption about how the grid was
generated. Repeated design discussion (2026-09-17) concluded that heuristics
of this kind cannot be validated or compared meaningfully until at least one
fully rigorous baseline exists: a strategy that is \emph{provably optimal}
for an \emph{explicitly stated} generative model $M$ and an \emph{explicitly
stated} objective $L$.

This logbook is that project. The plan (agreed 2026-09-17) is:
\begin{enumerate}
  \item Shrink the game to a size where every board, and every possible
  play-through, can be exhaustively enumerated by brute force --- so every
  claim can be machine-checked, not just argued.
  \item Get a genuinely optimal solver working and validated there.
  \item Scale up board size step by step, tracking exactly where and why
  brute-force techniques stop being tractable, and look for workarounds at
  each wall before conceding defeat.
  \item Keep this document updated as a persistent record, so a negative
  result (``exact solving becomes impractical beyond size $k$, for reason
  X'') is as valid and as carefully written up as a positive one.
\end{enumerate}

All code lives in \texttt{research/} on the \texttt{optimal-solver-research}
git branch, kept separate from the recreational tools so nothing here can
break them. All numeric results quoted below were produced by the code in
this directory and are reproduced by \texttt{research/tests/}.

\section{Model $M_1$: the generative process}

Parametrised by board size $n$ (the real game is $n=5$):
\begin{itemize}
  \item Alphabet size $= n^2+1$ (exactly one letter of the alphabet is
  absent from every grid, mirroring the real game).
  \item Grid is $n \times n$; \textbf{lines} (candidate word positions) are
  the $n$ rows, $n$ columns, and 2 diagonals: $2n+2$ in total.
  \item A fixed vocabulary $W$ of length-$n$ strings, each with $n$ distinct
  letters (not required to be English --- just a fixed toy dictionary for
  small $n$; the real \texttt{dict\_game.csv} is used once $n=5$).
\end{itemize}

$M_1$ generates a grid as:
\begin{enumerate}
  \item word $w \sim \mathrm{Uniform}(W)$
  \item line $p \sim \mathrm{Uniform}(\text{the } 2n+2 \text{ lines})$
  \item excluded letter $e \sim \mathrm{Uniform}(\text{alphabet} \setminus w)$
  \item the remaining $n^2-n$ letters are placed in the remaining $n^2-n$
  cells via a uniformly random permutation
\end{enumerate}
with \emph{no rejection step}. $M_1$ is deliberately the simplest
well-posed model, and is known to be wrong in at least one respect: the
2026-09-17 discussion raised the possibility that a real puzzle setter
rejects (and retries) any grid whose dross letters accidentally spell a
second valid word along some other line. That complication is deferred to
a future $M_2$; every result below is explicitly a result \emph{about
$M_1$}, not a claim about the real puzzle.

The excluded letter $e$ is told to the player before play starts (as in the
real game), so it is fixed per game instance rather than left as a live
hypothesis.

\subsection{Oracle}
\label{sec:oracle-fix}

Querying an untested letter $L \ne e$ deterministically returns \emph{the
one cell where $L$ actually sits in the grid} -- whether or not $L$ turns
out to be part of the answer word. If $L$ happens to be part of the answer
word, that cell is necessarily $p[\,w.\mathrm{index}(L)\,]$; if not, it is
whichever of the $n^2-n$ dross cells the generative process (step 4 above)
happened to place $L$ at. There is no ``not in the word, no location''
outcome: the grid is a full bijection over every non-excluded letter, so
every query resolves to a real cell. This matches \texttt{wordhunt.py}'s
actual bookkeeping -- every entry in its \texttt{revealed} dict is handled
identically by \texttt{word\_fits\_position} regardless of whether that
letter later turns out to be part of the answer.

(An earlier draft of this section, and the first implementation of
\texttt{query\_outcome} in \texttt{solver.py}, stated and coded the
opposite -- that a dross letter's query returns no location at all. That
was a real bug, found and fixed the same day; see
Section~\ref{sec:corrections} for how it was caught and what it broke
downstream.)

\section{Objective $L_1$}

Minimise $\mathbb{E}[\text{number of queries until the grid is uniquely
determined}]$ (equivalently, until $(w,p)$ is uniquely determined, in every
state reachable without a collision --- see Section~\ref{sec:corrections}
on why grid uniqueness, not $(w,p)$ uniqueness, is the well-posed target
once $M_1$ has no veto step, and on the still-open question of whether this
is stricter than the real game's actual win condition).

\section{Exact DP}

Let $H$ be the current set of \emph{candidate worlds} (full grids)
consistent with everything observed so far. Under $M_1$, every candidate
world is equally likely, so:
\begin{align}
V(H) &= 0 &&\text{if every remaining candidate has the same grid} \\
V(H) &= 1 + \min_{L} \sum_{\text{cell } c} \frac{|H_c|}{|H|}\, V(H_c)
&&\text{otherwise}
\end{align}
where $H_c \subseteq H$ is the subset of candidates in which $L$ actually
sits at cell $c$ (Section~\ref{sec:oracle-fix} on why this partitions by
concrete cell, with no separate merged ``$L$ absent'' bucket: the oracle
always discloses $L$'s true cell). Termination is on grid equality, not on
agreement of some tagged $(w,p)$ pair --- see
Section~\ref{sec:corrections} on why the latter can be an unanswerable
question when $M_1$ has no veto step.

The $\arg\min_L$ at the root is the provably optimal next query --- not a
proxy for it. This is implemented as \texttt{ExactSolver}, operating on
fully-enumerated worlds, in \texttt{solver.py}. (A second solver,
\texttt{PairSolver}, was written to operate directly on $(w,p)$ pairs
without full worlds, on the strength of a sufficiency argument in
Section~\ref{sec:lemma} below -- that argument is \textbf{retracted}; see
Section~\ref{sec:corrections}. \texttt{ExactSolver} on full worlds is the
only currently-trusted solver.)

Also implemented: \texttt{greedy\_choice}, the one-step
maximum-information-gain heuristic (i.e. choosing $L$ to maximise the
Shannon entropy of the outcome partition on its own, ignoring everything
beyond one query) --- the same style of proxy used throughout
\texttt{wordhunt2.py}. Comparing it against \texttt{ExactSolver} is the
central point of this exercise.

\section{The (word, line) sufficiency lemma}
\label{sec:lemma}

\textbf{RETRACTED (see Section~\ref{sec:corrections}).} The lemma below is
FALSE under the corrected oracle of Section~\ref{sec:oracle-fix}: a dross
letter's true cell depends on the specific dross permutation, which is not
determined by $(w,p)$ alone, so $(w,p)$ pairs are not in fact a sufficient
statistic. It held only under the earlier, buggy oracle (where a dross
query carried no location information at all, so there was nothing about
the permutation left to depend on). \texttt{PairSolver}, and every result
below and in Sections~\ref{sec:n4wall}--\ref{sec:n5wall} that relies on it,
are therefore also unsound as stated. Kept below, unmodified, as the
argument that was believed correct at the time and the historical
verification that was run against it -- not as a currently-trusted claim.

Full-world enumeration (build every literal grid $M_1$ can produce) is
combinatorially impossible beyond very small $n$: the number of ways to
permute the $n^2-n$ dross letters into the remaining cells is
$(n^2-n-1)!$.

\begin{center}
\begin{tabular}{cccc}
\toprule
$n$ & alphabet size & lines & dross permutations $(n^2-n-1)!$ \\
\midrule
2 & 5  & 6  & $2! = 2$ \\
3 & 10 & 8  & $6! = 720$ \\
4 & 17 & 10 & $12! = 479{,}001{,}600$ \\
5 & 26 & 12 & $20! \approx 2.43\times10^{18}$ \\
\bottomrule
\end{tabular}
\end{center}

\textbf{Lemma.} Under $M_1$, with the excluded letter $e$ fixed, every
$(w,p)$ hypothesis has \emph{exactly} the same number of full-world
realisations (the dross-permutation count depends only on $n$, not on which
word or line), so this factor is a constant that cancels out of every
relative-probability calculation. The exact DP can therefore be run
directly on $(w,p)$ pairs, weighting each equally, without ever
constructing a full grid.

\textbf{Verification (as it stood before the fix -- now invalid, see the
retraction notice above).} Rather than trust the algebra alone,
\texttt{tests/test\_pair\_solver.py} built both \texttt{ExactSolver} (on
fully-enumerated worlds) and \texttt{PairSolver} (on pairs only) for every
excluded-letter scenario at $n=2$ and $n=3$ and asserted the two reported
bit-identical $V(H_0)$; under the buggy oracle then in use, both did pass.
Once the oracle was corrected, the same tests were re-run and now fail
(kept in the suite as \texttt{xfail}/\texttt{skip}, deliberately, per
Section~\ref{sec:corrections}) -- the ``verification'' this paragraph
describes verified the wrong model self-consistently, not the real one.

Had it remained valid, this would have removed the dross-permutation
factorial as an obstacle entirely, independent of the DP's own
combinatorial cost (the separate wall in Section~\ref{sec:n5wall}, also
now superseded). That structural point --- factorial-avoidance and
DP-cost are two distinct obstacles --- still stands even though the
specific lemma that was going to deliver the first one does not.

\textbf{Finding 2 (the headline result so far).} In 6 of the 10
scenarios, one-step maximum-entropy greedy selection is \emph{strictly}
worse than the true optimum --- not by a rounding error, but by a
consistently reproducible margin (e.g. excluded=`c': 2.55 vs.\ 2.50). This

one-step information gain as ``the'' optimal-play criterion, of exactly the
kind known from optimal Mastermind/Wordle solvers: two letters can tie (or
nearly tie) on immediate information gain while differing in how good a
position they leave for the \emph{next} query. Every number above is
exact (not simulated) and was solved in under 1.5s per scenario
(\texttt{research/tests}, and the ad-hoc script in the git history of this
branch).

This directly undercuts every ``pick the highest-entropy/highest-Bayes-mass
letter'' heuristic used by \texttt{wordhunt2.py} to date: even granting
their weighting assumptions, one-step greedy selection on top of them is
demonstrably not the same thing as optimal play.

\section{The $n=4$ wall (diagnosed, and defused)}
\label{sec:n4wall}

\textbf{SUPERSEDED (see Section~\ref{sec:corrections}).} This section's
conclusion (``thanks to the sufficiency lemma, this does not matter'')
relies entirely on the retracted lemma of Section~\ref{sec:lemma}. The
dross-permutation factorial obstacle described below is real and correctly
diagnosed; the claimed resolution (via \texttt{PairSolver}) is not
currently valid. $n=4$ should be considered unaddressed again until a
correct pair-based (or otherwise sub-factorial) solver exists.

Full-world enumeration is impossible at $n=4$ (Section~\ref{sec:lemma}'s
table: $12! \approx 4.8\times10^8$ dross permutations per (word, line,
excluded) choice). Thanks to the sufficiency lemma, this does not matter:
\texttt{PairSolver} needs no full worlds, and its state space at $n=4$ is
just (number of candidate words) $\times$ (10 lines) -- no factorial term
at all. The real question is whether \emph{that} state space is tractable,
which turns out to depend overwhelmingly on $n$ (alphabet/branching factor)
and vocabulary size rather than on the factorial term that looked scary at
first glance.

\textbf{Finding 3.} The real \texttt{dict\_game.csv} has 10{,}176
candidate words, i.e.\ roughly \emph{300$\times$} the 30-word sample that
already took 10 seconds and 40{,}000 memoised states. Extrapolating even
the optimistic end of the observed growth curve, exact full-lookahead
solving at real $n=5$ scale, from the fully-uninformed opening state, is
not a performance-tuning problem --- it is many orders of magnitude beyond
reach on this hardware, and almost certainly on any hardware, without a
fundamentally different algorithmic approach (see
Section~\ref{sec:nextsteps}).

Importantly, this wall is a property of $n$ (i.e.\ the branching factor:
up to 21 queryable letters at $n=5$ vs.\ up to 7 at $n=3$) and of how
\emph{early} in the game the search starts (the fully-uninformed opening
state has the largest candidate set the game ever sees), much more than it
is a property of vocabulary size on its own: Section~\ref{sec:n3}'s
$n=3$ instances, with comparable vocabulary sizes (5--8 words) but a
6--7-letter query alphabet instead of a 21-letter one, solved in
well under a second.

\section{Next steps}
\label{sec:nextsteps}

Not yet attempted, in rough order of expected value:

\begin{enumerate}
  \item \textbf{Branch-and-bound with a provable lower bound.} A node can
  be pruned the moment its best-case remaining cost (e.g.\ $\log$ of the
  branching factor) already exceeds the best solution found so far. This
  preserves exactness (no silent fallback to a heuristic) while potentially
  cutting large amounts of dead search.
  \item \textbf{Solve from mid-game states, not the opening.} A real player
  only needs an exact answer from \emph{wherever they currently are} --
  typically well past the opening, with the candidate set already
  substantially pruned by revealed cells. Section~\ref{sec:n5wall}'s wall
  is specifically about the worst case (opening, full 10k-word dictionary);
  it may still be exactly solvable a few queries in, once $|H|$ has
  naturally shrunk. Worth measuring directly rather than assuming.
  \item \textbf{Depth-limited exact search with a reported bound.} Search
  exactly to some fixed depth $d$, and for states beyond that, report a
  provable interval (not a guess) rather than a heuristic point estimate --
  matches the ``never bluff a heuristic under the optimal-solver label''
  principle from the design discussion.
  \item \textbf{Model $M_2$}: reintroduce the ``dross letters must not
  accidentally spell a second word'' rejection step raised on 2026-09-17,
  and check whether $M_1$'s uniform-pair-weighting result changes
  qualitatively once that's modelled, at whatever board size remains
  tractable.
  \item \textbf{A different objective $L_2$}: $\mathbb{E}[(\text{queries})^2]$
  requires tracking two moments through the Bellman recursion instead of
  one; algebraically routine but not yet implemented.
\end{enumerate}

\textbf{SUPERSEDED (see Section~\ref{sec:corrections}).} The paragraph
below asserted ``verified at toy scale ($n\le3$)'' -- that is no longer
established: $n=3$ under the corrected oracle has not been observed to
terminate. Only $n=2$ is currently verified. The shape of the argument
(exact play is achievable at small scale, uncertain at $n=5$, greedy is
not a substitute) may still be right, but should be read as a hypothesis
to re-check, not a settled conclusion.

It is entirely possible that the honest endpoint of this project is a
short paper whose conclusion is: exact optimal play is achievable and
verified at toy scale ($n\le3$), is real and worth verifying at $n=5$ from
\emph{sufficiently-advanced} mid-game states, but is fundamentally out of
reach for the opening move against a realistic dictionary -- and greedy
one-step heuristics, however dressed up, are not a substitute for it (only
a proxy of unknown and state-dependent quality, per Section~\ref{sec:n3}).
That would be a complete and legitimate result, not a failure to reach one.

\section{Corrections (2026-09-17, same day)}
\label{sec:corrections}

Per this logbook's stated practice, errors found in the results above are
recorded here rather than silently rewritten. \textbf{Every numeric result
in Sections~\ref{sec:results}--\ref{sec:n5wall} was computed under a wrong
oracle model} and should be treated as superseded pending re-derivation.

\subsection{Bug 1: the oracle model was wrong}

The original \texttt{query\_outcome} returned \emph{no location at all}
when a queried letter was not part of the answer word. This is not what
the real game does, and not what \texttt{wordhunt.py} implements: the grid
is a full bijection over every non-excluded letter, so querying any letter
always resolves to its one true cell, whether or not that letter turns out
to be part of the answer. A "not in the word" outcome never occurs as a
distinct case in \texttt{wordhunt.py}'s bookkeeping -- every entry in
\texttt{revealed} is handled identically by \texttt{word\_fits\_position}
regardless of whether it later turns out to be dross. \texttt{query\_outcome}
has been corrected to always return the letter's true cell.

This is the same category of mistake as the earliest abandoned "F(L$\mid$G)"
attempt from the original design discussion (modelling where a dross
letter "would be"), recurring in a new piece of code -- worth remembering
next time an oracle-behaviour assumption is written down without a test
against brute-force enumeration first.

\subsection{Bug 2: the stopping condition was ill-posed without a veto step}

Fixing bug 1 immediately exposed an infinite loop in the DP. Diagnosis: at
$n=2$, excluded=`e', two \emph{different} generative paths --
$w=$``ab'' along the top row, and $w=$``cd'' along the bottom row -- can
produce the \emph{identical} grid:
\begin{lstlisting}
World A: word='ab', line=top row     grid={(0,0):a,(0,1):b,(1,0):c,(1,1):d}
World B: word='cd', line=bottom row  grid={(0,0):a,(0,1):b,(1,0):c,(1,1):d}
SAME GRID? True
\end{lstlisting}
No sequence of oracle queries can ever tell these apart, because the
oracle's answers are a pure function of the grid, and the grid is
identical. The DP's termination check (`is the tagged (word,line) unique?')
was asking an unanswerable question and looped forever trying to resolve
it. This is exactly the concern raised when $M_1$'s lack of a veto step
was agreed to: \emph{"if you choose to do that you must then be clear
about the stopping condition."} It surfaced as a literal bug rather than
staying a hypothetical.

\textbf{Fix}: termination is now defined on \emph{grid} uniqueness, not
tagged-pair uniqueness -- i.e.\ $M_1$'s well-defined notion of "solved" is
"the grid is fully reconstructed," which coincides with "the designated
answer is known" except exactly in a collision, where the latter is
genuinely unknowable and the former is the most that can honestly be
claimed.

\textbf{Measured collision rate} (fraction of raw, unvetoed $M_1$ worlds
whose grid happens to spell more than one dictionary word somewhere):

\begin{center}
\begin{tabular}{ccc}
\toprule
$n$ & vocabulary size & collision rate \\
\midrule
2 & 5 words & 69\% (all excluded-letter scenarios) \\
3 & 5--7 words & 4.3\%--8.2\%, depending on excluded letter \\
\bottomrule
\end{tabular}
\end{center}

The $n=2$ figure is inflated by an unrealistically small, densely
overlapping toy vocabulary (a 5-word cycle on a 5-letter alphabet), but the
$n=3$ figures are a genuine, measured answer to "how significant a
departure is it to skip the veto step?": even a tiny 5--7-word vocabulary
already produces an ambiguous grid 1 time in 12--25. This is direct
evidence (not argument) that $M_2$ (with the veto step) is not an optional
refinement -- it is needed for $M_1$ to be a reasonable model of the real
game at all, exactly as anticipated in the original design discussion.

\subsection{Consequence: exact solving got much harder (but not
intractable -- correction 2026-09-18)}

The corrected oracle is more informative per query (up to $n^2$ distinct
outcomes -- which cell -- versus the old model's effectively $\le n+1$),
which sounds like it should make the game easier to solve. It does not
make the \emph{search} easier: richer outcomes mean a larger branching
factor at every DP node, and the number of distinct reachable candidate
sets explodes correspondingly. Concretely, at $n=3$, excluded=`a' (5
candidate words, only 28{,}800 worlds -- trivial under the old, wrong
oracle, solved in $<1$s with $\sim$100 memoised states): under the
corrected oracle, \texttt{ExactSolver} passed 700{,}000 memoised states
without terminating within 20 seconds. $n=2$ remains fully tractable
(re-solved below).

\emph{Correction, 2026-09-18:} the claim above that this "did not
terminate" was wrong -- it terminates in 26.5s at 767,832 memoised states,
comfortably within reach; 20 seconds simply wasn't tried for long enough
before concluding intractability. This was an error of impatience, not of
model or algorithm, but it is exactly the kind of claim this project
exists to catch by testing rather than assuming -- see
Section~\ref{sec:n3-redo} for the full, corrected $n=3$ re-verification.

\subsection{Consequence: the (word, line) sufficiency lemma is retracted}

Section~\ref{sec:lemma}'s lemma held under the old oracle because a dross
letter's outcome (``absent'') genuinely didn't depend on anything beyond
(word, line). Under the corrected oracle, a dross letter's revealed cell
depends on the specific permutation of the remaining letters, which is
\emph{not} determined by (word, line) alone, and whose distribution over
remaining cells stops being uniform across surviving pairs once some cells
have already been revealed (precisely the complication that broke the very
first F(L$\mid$G) attempt). \texttt{PairSolver} still silently implements
the old model and is simply wrong now; its equivalence tests are kept in
\texttt{tests/test\_pair\_solver.py} but marked \texttt{xfail}/\texttt{skip}
with an explanation, as the documented record of the retraction rather than
being deleted. A correct pair-based (i.e.\ not full-world) solver requires
properly counting consistent completions per pair given the revealed
history so far -- not yet attempted.

\subsection{Open question, not yet resolved: what does "winning" require?}

Grid-uniqueness termination is \emph{sound} (it can't loop forever, and it
never claims certainty it doesn't have), but it may be stricter than
necessary. The real game's actual win condition is presumably "the player
can read off some line that is certainly a complete, valid word" -- not
"every dross cell is known." Those two conditions coincide throughout
almost the entire game, and differ only in collision states, where "the
designated word" is unknowable but "some certainly-correct line" might
still not require full grid knowledge either way. A closer-to-real
definition would be: stop as soon as some $(w,p)$ is spelled by
\emph{every} remaining consistent grid (not necessarily the one tagged as
"designated," and not necessarily requiring every other cell to be
pinned down too). This was noticed, not yet implemented, and the 2.944
figure above should be read as an upper bound on expected queries under
the real win condition, not necessarily the answer to the question we
actually care about.

\textbf{Resolved 2026-09-18 (see Section~\ref{sec:mopup}):} neither the
grid-uniqueness termination above nor the closer-to-real guess was right.
There are three distinct quantities in play: (a) logical tag certainty
(the candidate set collapses to one designated $(w,p)$ pair by
elimination) -- but the real game does \emph{not} stop here, it grants no
early exit for merely knowing the answer; (b) logical grid certainty (all
$n^2$ cells' values are deducible by elimination) -- also not the real
rule, and \emph{also not simply "more than" (a) and (c) in the way first
assumed here}; (c) the true line's own $n$ cells \emph{operationally,
individually queried} (not merely deducible) -- this is the real rule.

\textbf{A same-day second correction, since the first attempt above (in
the version of this paragraph originally written) also got it wrong:} it
claimed (a) $\le$ (c) $\le$ (b) always. That is false, and Section~\ref{sec:mopup}
found the counterexample directly rather than by further armchair
reasoning: at $n=2$, grid-certainty (b) is measured at 2.09, strictly
\emph{below} mop-up (c) at 2.27. The reason is that (a) and (b) are both
\emph{deductive} quantities -- reachable purely by elimination, without
ever directly querying the cells they concern -- while (c) is an
\emph{operational} one: mop-up specifically requires those $n$ cells to
have been individually, directly queried, with no shortcut via inference.
Deduction can outrun the mandatory direct reveal or fall behind it
depending on how much cross-referencing power the vocabulary structure
gives elimination, so (b) and (c) are simply not ordered in general. What
\emph{is} always true, because it is a logical implication rather than an
empirical race: (a) $\le$ (b) (grid certainty implies tag certainty) and
(a) $\le$ (c) (completing mop-up implies you now know the tag too, but
tag certainty could have arrived earlier by elimination). See
Section~\ref{sec:mopup}'s \texttt{TagIdentifySolver} for the solver that
is actually valid to compare \texttt{MopUpSolver} against, and why
\texttt{ExactSolver} (grid-based) is not.

\section{2026-09-18: the real scoring rule, $M_2$ at $n=2$, and $n=3$ redone}
\label{sec:mopup}

Two points raised by review of the previous day's entry, both real and
both implemented here, working entirely at $n=2$ as requested (this
section is deliberately thorough at that one size rather than rushing to
scale up, per the request that prompted it).

\subsection{The real objective: mop-up cost, not certainty}

The real game does not end when the hypothesis space collapses to
certainty. It ends only when the oracle observes that every cell of the
(unique, under $M_2$) true line has been individually revealed by a
direct query -- so deducing the answer with 2 of its letters still
untested still costs 2 more turns, spent confirming exactly those
letters, before the game reports how many turns it took. Every previous
objective in this logbook (Sections~\ref{sec:results}--\ref{sec:n5wall}
and even the corrected Section~\ref{sec:corrections}) computed something
else: expected queries to \emph{certainty}, not to \emph{game end}.

This matters strategically, not just numerically: a query landing on a
true-line cell does double duty (it narrows the hypothesis space \emph{and}
advances the mandatory mop-up), while a query landing on dross only does
the former. A policy optimising for fastest certainty need not be the
policy optimising for fastest mop-up-inclusive game end.

\textbf{Definition.} $T := $ the query count at which $\mathrm{line}(w^*)
\subseteq \mathrm{Revealed}$, where $w^*$ is whichever candidate is
secretly true. Objective: minimise $\mathbb{E}[T]$.

\subsection{$M_2$: the veto, implemented and measured}

$M_2$ is $M_1$ with the simplest veto policy already coded in
\texttt{enumerate\_worlds(..., reject\_collisions=True)}: any grid whose
dross letters happen to also spell a second dictionary word along some
other line is discarded. Because $M_2$ never permits two valid words to
coexist in the true grid, the earlier grid-uniqueness termination
(Section~\ref{sec:corrections}) is no longer needed to avoid the
identical-grid ambiguity: under $M_2$, at most one candidate can ever have
its own line fully covered by the true history at a time, so "some
candidate's own line is now fully revealed" is unambiguous again.

\textbf{Some (word, line) choices are unreachable under $M_2$.} A sharp
observation from review: since $M_2$ discards any grid where the dross
happens to spell a second word, it's possible for a specific (word, line)
combination to have \emph{zero} surviving completions -- no arrangement of
the leftover letters avoids a collision -- and this can depend on which
line, not just which word (a word banned from the bottom row might be
fine on the top row, since the fixed cross-cutting cells differ). Measured
directly for \texttt{WORDS\_N2} = \{ab, bc, cd, de, ea\} (all $5\times4=20$
possible (word, line, excluded) triples per word, $90$ total across the
vocabulary):

\begin{center}
\begin{tabular}{cc}
\toprule
quantity & value \\
\midrule
total (word, line, excluded) triples & 90 \\
triples with zero surviving $M_2$ completions & 40 (44\%) \\
\bottomrule
\end{tabular}
\end{center}

44\% is almost certainly inflated by this vocabulary's pathological
structure (a 5-word cycle on a 5-letter alphabet, chosen originally for
having "a little overlapping structure," which turns out to mean
\emph{a lot} at $n=2$) -- a less densely-overlapping toy vocabulary would
presumably show a smaller rate, and the design discussion's own intuition
was that this effect is "vanishingly unlikely" at the real game's $n=5$.
But the qualitative phenomenon is confirmed, not just plausible: entire
(word, line) combinations really can be structurally impossible once
uniqueness is enforced, and it really can depend on which line the word
would occupy, not merely which word it is. (Verified by
\texttt{test\_some\_word\_line\_choices\_are\_unreachable\_under\_m2}, and
\texttt{test\_m2\_veto\_actually\_removes\_collisions} confirms every
surviving $M_2$ world genuinely spells exactly one dictionary word
somewhere, not merely "at most one long the designated line".)

\subsection{\texttt{MopUpSolver}: exact DP for the real objective}

Implemented as \texttt{MopUpSolver} in \texttt{solver.py}. State is
$(H, \mathrm{Revealed})$ -- candidate set \emph{and} the revealed-cell
set explicitly, not $H$ alone: two different query histories can leave
the same surviving-candidate set behind while having incidentally
revealed different amounts of whichever line turns out to be true, and
that difference changes $T$ directly. (Cell identity alone suffices,
without separately tracking which letter sits where: if a cell is already
revealed, every surviving candidate is already forced to agree on its
letter, by definition of "still consistent".)

\begin{align}
V(H, \mathrm{Rev}) &= 0 && \text{if every candidate in } H \text{ has } \mathrm{line}(w)\subseteq\mathrm{Rev} \\
V(H, \mathrm{Rev}) &= \tfrac{|A|}{|H|}\Big[1 + \min_L \sum_{c} \tfrac{|A_c|}{|A|}\, V(A_c,\, \mathrm{Rev}\cup\{c\})\Big] && \text{otherwise}
\end{align}
where $A\subseteq H$ is the subset not yet "done" (own line $\not\subseteq
\mathrm{Rev}$) and $A_c$ partitions $A$ by the cell $L$ resolves to.
Already-done candidates contribute $0$ to the expectation (their cost is
already fixed by an earlier turn) via the $|A|/|H|$ scaling, and are
dropped from further recursion. Unlike \texttt{ExactSolver}, a letter is
never skipped merely for failing to discriminate between active
candidates -- it can still be valuable by advancing mop-up for all of
them at once, and this objective must credit that.

One real bug caught while building this (not merely a design subtlety):
allowing the solver to consider re-querying an already-revealed letter
causes literal infinite recursion, not just wasted computation -- the
recursive call lands on the exact same $(H,\mathrm{Rev})$ state before it
is memoised. Already-revealed letters must be excluded from the letter
search outright, not left for the $\arg\min$ to (fail to) avoid.

\textbf{Triple validation.} \texttt{MopUpSolver}'s value at the root is
checked against two independently-coded computations that share no
formula with it or with each other: \texttt{simulate\_mopup\_policy\_}
\texttt{exact\_expectation} (an independent recursive re-derivation) and
\texttt{simulate\_mopup\_bruteforce} (literal step-by-step play against
every one of the $\le$36 worlds as ground truth, with no expectation
formula at all -- the closest thing available to "just play the game and
see"). All three agree exactly, for every excluded-letter scenario.

\subsection{(i) The mop-up-aware and identify-only policies genuinely
diverge, not just occasionally tie}

Method: solve \texttt{MopUpSolver} at the root (its own recursion tries
every letter, so its memo covers every state reachable under full
exploration, not just the states on its optimal path). For every
memoised state where MopUpSolver still had a genuine choice (i.e.\ was
not yet terminal), look up what \texttt{TagIdentifySolver} would have
chosen at the same candidate set (ignoring states where
\texttt{TagIdentifySolver} was \emph{already} certain -- comparing "what
would you do" against a solver with nothing left to decide is not a
meaningful comparison, it just reflects that mop-up still has mandatory
queries left after certainty, which is the entire point of
Section~\ref{sec:mopup}). Where the two solvers picked different letters,
computed the exact mop-up cost of forcing \texttt{TagIdentifySolver}'s
choice instead, to separate genuine strategic disagreement from harmless
tie-breaking (multiple equally-good letters, arbitrarily broken by
iteration order).

\textbf{$n=2$ (exhaustive, all 5 excluded-letter scenarios, all reachable
states):} 135 states where both solvers faced a real choice; 65
disagreed (48\%); \textbf{all 65 were genuine strategic divergences, zero
were ties} -- the worst single-state gap was a full extra expected query
if the tag-optimal choice were followed instead of the mop-up-optimal
one. This closes the "don't generalise from move 1 coincidence" caveat
from Section~\ref{sec:mopup} decisively: the two policies are not the
same policy, they only happened to agree at the very first move for that
particular (small, symmetric) vocabulary.

\textbf{$n=3$ (excluded=`a', sampled 3000 of $\sim$3.4M memoised
states):} kept deliberately bounded rather than exhaustive, both for
overnight resource-safety and because exhaustively re-solving
\texttt{TagIdentifySolver} from scratch at every one of millions of
distinct candidate sets was not a responsible use of an unattended
budget. Of the 3000 sampled states, 142 had both solvers still facing a
genuine choice; \textbf{138 of those (97\%) were real strategic
divergences}, none were ties, worst single-state gap again exactly 1.0
extra expected query. Consistent with, and if anything stronger than, the
$n=2$ result -- no sign that the divergence is an $n=2$ artifact that
washes out with more structure; if anything it looks more pervasive with
more structure to exploit.

\textbf{Conclusion for (i):} the mop-up-aware and identify-only
(tag-based) optimal policies are substantively different policies at
every board size checked so far, not merely different at isolated states
or only at the very first move. Any future heuristic or approximate
solver for this game needs to be built and evaluated against the
mop-up-aware objective specifically -- optimising for fastest certainty
and then treating the rest as "obviously fine because you already know
the answer" measurably leaves queries on the table.
